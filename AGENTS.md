# AGENTS.md

Instructions for any AI coding agent (or human) working in this repository.

## What this project is

A self-hosted, retrieval-grounded software engineering assistant. See
[README.md](README.md) and [docs/architecture.md](docs/architecture.md)
before making structural changes.

## Commands

```bash
# Backend (from backend/, inside its venv)
pip install -r requirements-dev.txt
ruff format app tests && ruff check app tests
mypy app
pytest --cov                                    # fast suite, no external services
pytest -m integration                            # needs Postgres/Redis/Qdrant/Ollama
alembic upgrade head

# Frontend (from frontend/)
npm ci
npm run lint && npm run format
npm test
npm run build
npm run test:e2e                                 # needs the full docker compose stack running

# Whole stack
docker compose up -d --build
python evals/run_evals.py --provider fake         # reproducible, offline
python evals/run_evals.py --provider ollama       # real model, needs Ollama running

# Infra
cd terraform/eks && terraform fmt -recursive && terraform validate
```

## Architecture boundaries

- `app/services/*` never imports from `app/api/*` — services are the
  reusable business logic; routes are thin adapters. If you find yourself
  importing a route into a service, the logic belongs in the service.
- Every provider with a "real" and "fake"/local implementation (LLM chat,
  embeddings, vector store) goes through a `Protocol` in `ports.py` and is
  obtained via a `get_*_provider()`/`get_vector_store()` factory keyed off
  `settings.llm_provider` — never instantiate `OllamaChatProvider` or
  `QdrantVectorStore` directly outside those factories.
- A `Citation` is only ever created from a chunk that was actually
  retrieved (`services/agents/citations.py`). Never construct one from raw
  LLM text without resolving it against `excerpts_by_index` first.
- Nothing applies a diff or runs a shell command from an LLM-proposed patch
  outside `services/patch/service.py`'s `decide_patch_proposal()` — that is
  the single human-approval gate. Do not add a second code path that can
  reach `services/patch/sandbox.py`.

## Truthfulness constraints (read this before claiming anything works)

- Never describe a workflow, migration, or infra change as "done" without
  having actually run it and having the command output to show for it.
- If you touch `services/agents/diff_extraction.py` or
  `services/patch/sandbox.py`, re-run the live-model verification described
  in `docs/testing.md` (or at minimum the relevant `tests/integration/`
  suite) — these were the source of three real, non-obvious bugs found only
  by running against a real Ollama model, not by unit tests against mocks.
- Don't loosen `pyproject.toml`'s `strict = true` mypy config, the ruff
  rule set, or the 70% coverage floor to make a change pass. Fix the
  underlying issue.
- `evals/eval_report_fake.json` and any `eval_report_ollama.json` must be
  regenerated by actually running `evals/run_evals.py`, never hand-edited.

## Release gate (all of this must pass before calling a change complete)

1. `ruff format --check`, `ruff check`, `mypy app` (backend) — clean
2. `pytest -m "not integration and not model_download"` — passing, coverage ≥ 70%
3. `npm run lint`, `npm run build` (frontend) — clean
4. `npx vitest run` (frontend) — passing
5. `docker compose up -d --build` — all services healthy
6. The three workflows (`/qa`, `/bug-investigations`, `/patch-proposals`)
   return real, citation-grounded responses against an ingested repository
7. `terraform fmt -check`, `terraform validate` if `terraform/` was touched
8. YAML-valid `k8s/` manifests if `k8s/` was touched
