# Security / threat model

## Assets

- User credentials and session tokens
- Ingested source code (potentially private-adjacent, even if only public
  repos are supported today) and its derived index (symbols, chunks,
  embeddings)
- The host filesystem the backend/worker runs on (reachable via the patch
  sandbox's subprocess execution)
- The LLM/embedding provider's availability and cost (if swapped for a paid
  hosted provider later)

## Authentication

- Passwords hashed with **Argon2id** (`argon2-cffi`), never stored or
  logged in plaintext.
- Access tokens are short-lived JWTs (15 min default). Refresh tokens are
  **opaque, random, single-use**, stored only as a SHA-256 hash
  (`RefreshToken.token_hash`) — a database read never discloses a usable
  credential.
- **Refresh-token reuse detection**: rotating a refresh token marks the old
  row `revoked_at` and links it to the new one (`replaced_by_id`). If a
  token whose row is already revoked is presented again — meaning it was
  used after being rotated, i.e. stolen and replayed — the entire chain
  from that token forward is revoked, forcing re-authentication. See
  `app/services/auth.py`.

## Authorization

- Every repository/patch-proposal lookup is owner-scoped
  (`api/deps.py::get_owned_repository`, `api/routes/patches.py::_get_owned_proposal`).
  A resource that exists but belongs to another user returns **404, not
  403** — deliberately, so an authenticated caller can't distinguish "not
  found" from "not yours" by response code, which would leak which
  repository/patch IDs exist.

## Repository ingestion (SSRF)

A "give me a URL and I'll clone it" endpoint is a classic SSRF vector.
`app/services/ingestion/security.py::validate_source_url` is the single
choke point every ingestion path goes through before any network call:

- Scheme allowlist: only `https://` (configurable, but `https`-only by
  default).
- Hostname resolved via `socket.getaddrinfo`, and **every** resolved IP is
  checked against private/loopback/link-local/multicast/reserved ranges
  (`ipaddress.IPv4Address`/`IPv6Address`'s `.is_private` etc.) — blocks
  cloud metadata endpoints (`169.254.169.254`), `localhost`, and internal
  network addresses. An unparseable/unresolvable host fails closed.
- Clone itself is bounded: `--depth 1`, a hard subprocess timeout
  (`INGESTION_CLONE_TIMEOUT_SECONDS`), and a post-clone size check
  (`INGESTION_MAX_REPO_SIZE_MB`) that rejects an oversized repo.

## Patch approval and the sandbox

**Nothing an LLM proposes is ever applied or executed automatically.**
`services/agents/workflows.py::run_patch_proposal` halts at a
`PENDING_APPROVAL` database row; the *only* code path that can move a
proposal past that state is `services/patch/service.py::decide_patch_proposal`,
which requires an authenticated, owner-scoped actor and records an
`ApprovalEvent` for every decision (approve or reject) — a full audit trail
of who approved what, when.

On approval, the diff is applied and its test command run only inside a
**disposable copy** of the repository (`services/patch/sandbox.py`), never
the canonical ingested clone the retrieval index was built from. See
[ADR 0003](adr/0003-process-level-sandbox-isolation.md) for exactly what
isolation this does and does not provide today — **it is process-level
isolation (a directory copy + a subprocess timeout), not a hermetic
container/VM sandbox**, documented honestly rather than oversold. No
network isolation and no per-run resource limits beyond the timeout exist
yet; this is an accepted trade-off specifically because the path is
human-approval-gated, not because the risk doesn't exist.

## Rate limiting

`slowapi`, Redis-backed in every environment except `test` (in-process
storage there, so the fast test suite never depends on a live Redis — a
real bug found and fixed during development, see `app/core/rate_limit.py`).
`/auth/register` and `/auth/login` have a tighter limit
(`RATE_LIMIT_AUTH`, default 10/minute) than the rest of the API.

## Secrets handling

- No real secret is committed anywhere in this repository.
  `backend/.env.docker` contains a clearly-labeled local-only JWT secret and
  MinIO's well-known public default credentials — safe because the whole
  stack only ever runs on `localhost`/the Compose network, never exposed.
- `k8s/02-secret.yaml.example` is a template; the real, filled-in
  `02-secret.yaml` is gitignored (`k8s/.gitignore`).
- Terraform's RDS password is generated by `random_password` and stored in
  AWS Secrets Manager (`terraform/eks/rds.tf`) — never written to a
  `.tfvars` file or Terraform output as plaintext.
- CI runs a secret-scan job (`gitleaks`) on every push/PR.

## Input validation

Every request body is a Pydantic model (`app/schemas/*.py`) — FastAPI
rejects malformed input before it reaches a route handler. File-based
inputs (ingested repository content) are read as text with
`errors="ignore"` rather than trusting encoding claims, and binary files
are skipped entirely during the ingestion walk (`services/ingestion/walker.py`).

## Dependency and container scanning

CI runs `pip-audit` (backend) and `npm audit` (frontend) — see
`.github/workflows/ci.yml`. Findings are not currently suppressed; if one
is ever accepted as a documented, time-bounded risk, it will be recorded
here with the reasoning, not silently ignored.

## Known limitations (not hidden)

- The patch sandbox's isolation model (above) is the single biggest
  documented gap between this project and a production-hardened version of
  itself.
- No WAF/DDoS protection at the application layer — expected to be handled
  by the deployment's ingress/load balancer in a real deployment (not
  provisioned by the Terraform module here).
- No email verification on registration (no email provider is wired up in
  this local-first vertical slice) — an unverified email can register and
  use the app immediately.
